= Links and References

This page collects prior art and useful background for code-centric knowledge graphs, repository graphs, and related vulnerability and LLM applications. Notes are brief signposts rather than full reviews. Every link, title, and venue below was re-verified in August 2026; publication statuses and project activity drift, so expect some skew over time.

== How this project is positioned

neo4j-code-graph does *not* compete in the agent-context category — the crowded space of local-first, many-language indexers that optimize token budgets for coding agents over embedded, per-checkout stores. Its differentiation is joining four signals in *one queryable Neo4j graph*: git history as a graph (Commit/Developer/FileVer/CO_CHANGED temporal coupling), versioned Maven dependency → CVE linkage (NVD + GHSA, version-range aware), a method-level CALLS graph, and GDS analytics. Cross-signal questions — "which team owns the code that most often calls this vulnerable dependency?" — become single Cypher queries here: joins the per-checkout agent-context indexes have no data to answer, because they index one checkout's code rather than its git history, dependency versions, or CVE exposure. CodeQL and Joern own proof-grade dataflow and taint analysis; this project is honest, ranked triage on a lexical graph — evidence, not proof.

== Foundations: code, history, and risk as a graph

* link:https://doi.org/10.1109/SP.2014.44[Yamaguchi et al., IEEE S&P 2014 — Modeling and Discovering Vulnerabilities with Code Property Graphs] (link:https://mlsec.org/docs/2014-ieeesp.pdf[PDF]) — The founding paper for graph-database code security analysis: merges AST, control flow, and program dependencies into one property graph — stored in Neo4j — and uses graph traversals to uncover 18 previously unknown Linux kernel vulnerabilities.
* link:https://doi.org/10.1109/WCRE.2009.19[D'Ambros, Lanza & Robbes, WCRE 2009 — On the Relationship Between Change Coupling and Software Defects] — Empirical evidence that files which repeatedly change together correlate with defects; the peer-reviewed foundation for this project's CO_CHANGED temporal-coupling signal.
* link:https://yanjiezhao96.github.io/files/zhao2019knowledge.pdf[Zhao et al., IEEE SANER 2019 — Knowledge Graphing Git Repositories] — An early knowledge-graph schema over git repositories connecting commits, files, and changed methods to enable advanced queries and exploration.
* link:https://arxiv.org/abs/2002.09440[Abdelaziz et al., K-CAP 2021 — A Toolkit for Generating Code Knowledge Graphs (GraphGen4Code)] — Builds a large-scale machine-interpretable knowledge graph over ~1.3M Python programs, linking code structure to documentation and forum content.
* link:https://arxiv.org/abs/1806.05893[Ponta, Plate & Sabetta, ICSME 2018 — Beyond Metadata: Code-centric and Usage-based Analysis of Known Vulnerabilities in Open-source Software] — The founding paper for code-centric SCA in the Java/Maven ecosystem (SAP's VULAS, later open-sourced as Eclipse Steady): decide whether vulnerable library code is actually reachable instead of trusting metadata-level version matching.
* link:https://arxiv.org/abs/2301.07972[Mir et al., SANER 2023 — On the Effect of Transitivity and Granularity on Vulnerability Propagation in the Maven Ecosystem] — Call-graph reachability over ~3M Maven packages: fewer than 1% have an actual reachable path to vulnerable dependency code, versus roughly a third flagged by dependency-level matching — the empirical case for reachability-ranked CVE triage.
* link:https://pragprog.com/titles/atcrime2/your-code-as-a-crime-scene-second-edition/[Adam Tornhill — Your Code as a Crime Scene, 2nd ed. (Pragmatic Bookshelf, 2024)] — The standard industry text on mining version-control history for hotspots and change coupling to rank change risk; this pipeline materializes those techniques as first-class graph elements.

== Code graphs for LLMs and coding agents (published)

* link:https://arxiv.org/abs/2410.14684[Ouyang et al., ICLR 2025 — RepoGraph] — Plug-in repository-level code graph that improved all four SWE-bench frameworks it was attached to, agentic and procedural alike; evidence that deterministic repo graphs lift LLM software engineering.
* link:https://arxiv.org/abs/2408.03910[Liu et al., NAACL 2025 — CodexGraph] — LLM agents write graph-database queries over a repository code graph for structure-aware retrieval; the closest published architecture to this project's query-first design.
* link:https://arxiv.org/abs/2503.09089[Chen et al., ACL 2025 — LocAgent] — Parses repositories into directed heterogeneous graphs so LLM agents can localize change targets via multi-hop graph reasoning.
* link:https://arxiv.org/abs/2406.07003[Liu et al., ASE 2024 — GraphCoder] — Statement-level code context graph (control/data dependence) driving repository-level completion retrieval.
* link:https://arxiv.org/abs/2505.16901[Tao et al., NeurIPS 2025 — Code Graph Model (CGM)] — Integrates repository code-graph structure directly into an LLM's attention for repository-level software engineering tasks.
* link:https://arxiv.org/abs/2505.14394[Athale & Vaddina, LLM4Code 2025 — Knowledge Graph Based Repository-Level Code Generation] — Represents repositories as knowledge graphs (File/Class/Method and description nodes) to improve retrieval for code generation.

== Preprints and recent work

* link:https://arxiv.org/abs/2601.08773[Reliable Graph-RAG for Codebases: AST-Derived Graphs vs LLM-Extracted Knowledge Graphs (2026 preprint)] — Benchmarks deterministic tree-sitter AST graphs against LLM-extracted KGs on Java repositories; finds the deterministic graphs give better correctness, faster indexing, and lower cost — direct support for this project's deterministic-extraction design.
* link:https://arxiv.org/abs/2503.21710[KGCompass (2025 preprint)] — Repository-aware knowledge graph linking issues, pull requests, files, classes, and functions, path-guiding an LLM for software repair.
* link:https://arxiv.org/abs/2507.20502[VDGraph (ACM SAC 2026)] — Merges SBOM dependency data and SCA vulnerability findings into a Neo4j knowledge graph across 21 Java projects; shows vulnerability exposure concentrates in transitive dependencies three or more levels deep.
* link:https://arxiv.org/abs/2506.18050[VFArchē (2025 preprint)] — Locates the actual vulnerable functions behind CVE advisories (even without patches) and cuts SCA false positives by 78–89% when paired with reachability analysis — the direction method-level CVE triage is heading.
* link:https://arxiv.org/abs/2507.19942[Prometheus (2025/2026 preprint)] — Memory-augmented multi-agent framework representing a repository as a unified knowledge graph for issue resolution (retitled in v2 to "Towards Long-Horizon Codebase Navigation for Repository-Level Problem Solving").
* link:https://arxiv.org/abs/2510.04905[Retrieval-Augmented Code Generation survey (2025 preprint)] — Survey of repository-level RAG covering context construction, retrieval optimization, and generation.
* link:https://arxiv.org/abs/2411.11532[CKGFuzzer (ICSE 2025 Companion)] — Builds an interprocedural code knowledge graph and drives LLM agents over it to generate fuzz drivers; code-KG-grounded security tooling.

_Historical note:_ link:https://arxiv.org/abs/2203.03850[UniXcoder (Guo et al., ACL 2022)] powered this project's method-embedding/KNN-similarity stage, which was removed in 2026 during the repositioning toward change-risk and vulnerability-reachability intelligence.

== Code graphs in industry

* link:https://www.uber.com/us/en/blog/efficient-software-factory/[Uber (2026) — Running a Software Factory Efficiently at Uber Scale] — Uber's AI Context Graph: a unified graph of 24 million nodes and 80 million edges integrating services, teams, incidents, pull requests, design docs, deployments, and datasets from over 30 internal systems — the grounding layer that lets coding agents find engineering context in seconds instead of minutes.
* link:https://www.youtube.com/watch?v=gNJgt_IB--E[Uber at GraphSummit NYC 2025 — Uber's Config Knowledge Graph: GenAI with GraphRAG and MCP] — Vignesh Murugesan (Senior Staff Engineer, Uber) on building Uber's config knowledge graph on Neo4j — chosen over Uber's homegrown graph stores for ACID transactional guarantees — with GraphRAG and MCP on top.
* link:https://martinfowler.com/articles/legacy-modernization-gen-ai.html[Thoughtworks (martinfowler.com, 2024) — Legacy Modernization meets GenAI] — Describes CodeConcise, Thoughtworks' modernization accelerator built on a code knowledge graph, naming Neo4j as "our graph database of choice" for holding the enriched knowledge graph.
* link:https://codescene.com/[CodeScene] — Commercial behavioral code analysis (hotspots, knowledge maps, change coupling mined from git history, per Tornhill's work); the closest commercial analogue to this project's temporal-coupling and ownership signals.

== Neo4j-based open-source prior art

* link:https://github.com/jQAssistant/jqassistant[jQAssistant] — Scans Java projects into Neo4j and validates architecture and dependency rules written as Cypher queries; long-established and actively developed — the nearest architectural neighbor to this project.
* link:https://github.com/JohT/code-graph-analysis-pipeline[JohT/code-graph-analysis-pipeline] — Fully automated jQAssistant + Neo4j pipeline for Java/TypeScript code graphs: graph algorithms, node embeddings, git-history co-change mining, and ML-based anomaly detection.
* link:https://github.com/ChrisRoyse/CodeGraph[ChrisRoyse/CodeGraph] — Multi-language static analysis (TS/JS, Python, Java, C#, C/C++, Go, SQL) into a queryable Neo4j graph with MCP integration; dormant since mid-2025.
* link:https://github.com/JonnoC/CodeRAG[JonnoC/CodeRAG] — Maps classes, methods, dependencies, and CK quality metrics for TypeScript/JavaScript, Java, and Python into Neo4j to give AI assistants contextual code intelligence.
* link:https://github.com/eric050828/graph-codebase-mcp[eric050828/graph-codebase-mcp] — Parses Python code (AST + embeddings) into a Neo4j knowledge graph exposed to AI agents through an MCP server.
* link:https://github.com/mufasadb/code-grapher[mufasadb/code-grapher] — MCP server combining a Neo4j code graph with vector search to feed AI assistants precise code context.
* link:https://github.com/brutski/go-code-graph[brutski/go-code-graph] — Analyzes Go codebases into a Neo4j graph and exposes call-path and architectural queries over MCP.
* link:https://github.com/vladbatushkov/strazh[vladbatushkov/strazh] — Builds a knowledge graph of a C# codebase with the Roslyn API and stores it in Neo4j.
* link:https://github.com/neo4j-contrib/mcp-neo4j[mcp-neo4j (Neo4j Labs)] — MCP servers maintained by Neo4j's Field GenAI team (natural-language→Cypher, graph memory, Aura API, data modeling); a good *companion* to this project's curated MCP tools. The officially supported product MCP server is link:https://github.com/neo4j/mcp[neo4j/mcp].

== Complementary deep static analysis

* link:https://github.com/github/codeql[CodeQL] — The query-based static analysis engine behind GitHub code scanning, with real interprocedural dataflow/taint tracking. Use it when you need dataflow-level evidence; this project's CALLS edges are receiver-class + arity matched lexical triage.
* link:https://joern.io/[Joern] — Open-source code property graph platform for interactive vulnerability research (its own embedded graph store); the direct descendant of Yamaguchi et al.'s CPG work above.
